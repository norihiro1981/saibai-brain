## 2026-11-03（火）SwitchBot の実機の試し（`spikes/switchbot/`）
- 進め方：書く前に公式の README（OpenWonderLabs/SwitchBotAPI）と、機器ごとの資料（温湿度計プラス・プラグミニ（JP）・ハブ）、BLE の資料（OpenWonderLabs/SwitchBotAPI-BLE の meter.md）を `gh api` で読んだ。スクリプトは 1 本 1 手順で、PEP 723 の書き方にして `uv run --script` で動かす。鍵は python-dotenv でプログラムの中だけで読む。ID はファイルに書かず、その都度一覧から種類で引く（.env にあればそちらを使う）。生の記録は `spikes/logs/`。
- **例外・スタンドだけ**：手順 4 では、守りの層を通さずにプラグを API で動かした。先は電気スタンドだけで、加湿器はつないでいない。このスクリプトは本体のコードからは呼ばない。始めと終わりは必ず「切」にする。
- できた
  - 機器の一覧：ハブミニ・プラグミニ（JP）・温湿度計プラスの 3 台が出た。温湿度計の `hubDeviceId` はハブミニ。プラグは Wi-Fi で直につながる（`000000000000`）。
  - 温湿度計をクラウドで読む：19.1℃・60%・電池 100。往復は 0.1〜0.3 秒（一度だけ 3.7 秒）。
  - プラグの 入→切 を 3 回：命令は毎回 `statusCode=100`。状態の `power` は**命令の 1 秒後はまだ前のまま、3 秒後には切り替わっていた**（6 回とも同じ）。終わりは「切」になっているのを確かめた。
- 資料と違った・分かったこと
  - 署名：README の本文には「token+t を HMAC して大文字に」とあるが、例のコード（Python 3）は「token+t+nonce を HMAC して base64」。例のコードのほうで通った。
  - クラウドの温湿度の値には**時刻が付かない**（返る鍵は battery・humidity・temperature・version など）。応答の `Date` ヘッダは「読んだ時刻」であって、「測った時刻」ではない。時刻が付くのは Webhook（`timeOfSample`）だけ。
  - プラグミニ（JP）の状態に、資料には無い `power`（"on"/"off"）が返る。始めた時は「入」だった（前から入っていた）。
  - プラグの `electricCurrent` と `weight` は、「入」の間もずっと 0 だった。スタンドのスイッチが切れていたのか、値の更新が遅いのかはまだ分からない。電流だけでは「本当に通電したか」を確かめられていない。`electricityOfDay` は 0 から 23 に飛んだ。
- BLE（手順 3）
  - Claude Code のアプリの中から bleak を動かすと、macOS が Bluetooth の許可の無いプロセスとして落とす（終わりの番号は 134）。ターミナルから人が動かすと、10 分の記録がとれた。
  - 届き方：10 分で 60 回届いた（同じ発信が 2 回ずつ届くので、それは 1 回に数えた）。間隔は中央 6 秒・最大 38 秒。始めてから初めて届くまでに約 20 秒かかった。
  - 解き方：資料の Byte3〜5 の表のとおりに解けた（例：19.0℃・61%・電池 100）。
  - 資料と違った点：種類の字は表に無い `'i'`（0x69）だった。Service data の UUID は資料の `cba20d00…`／`fee7` ではなく `0000fd3d-…`、製造者の ID は資料の `0x0059` ではなく `0x0969` だった。製造者データには MAC が入っていて（macOS では機器の MAC が見えないので、これで見分けた）、その後ろにも同じ温湿度のバイトが並んでいる。
  - クラウドとの差：BLE は 19.0℃・61% なのに、クラウドは 8 分のあいだ 19.1℃・60% のままだった。BLE が 18.9℃・61% に変わってから（532 秒目）、クラウドも 18.9℃・61% になった（547 秒目の読み）。**クラウドは小さな変化をすぐには上げない**。遅れは 15 秒以内だが、クラウドを 60 秒おきに読んだので粗い。
  - 見えたこと：温湿度は BLE のほうが新しく細かい。クラウドの値には時刻が無いので、古いまま止まっているのかを見分けられない。
