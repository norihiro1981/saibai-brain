# 栽培室の環境記録（2 期間・約 1 分ごと）

兵庫県の栽培室（コーヒーの幼木）で、ラズパイで集めた記録の一部です。夏と秋の 4 週ずつを切り出しています。

## ファイル

| ファイル | 期間（JST） | 行数（見出しを除く） | 大きさ |
|---|---|---:|---:|
| `summer_2026-08-15_2026-09-11.csv` | 2026-08-15（土）00:00 〜 2026-09-11（金）23:59 | 158,529 | 8,049,555 バイト |
| `autumn_2026-10-03_2026-10-30.csv` | 2026-10-03（土）00:00 〜 2026-10-30（金）23:59 | 118,935 | 5,946,870 バイト |

- 夏の期間は、栽培室に加湿器を置いた日の翌日から 4 週です。週の切り方は土曜〜金曜。
- 1 行＝1 台の機器の 1 回の読み（縦に長い形）。時刻順に並んでいます。
- 値は記録のままです（間引き・平均・補間・平滑化・補正はしていません）。

## 列

| 列 | 意味 | 単位 |
|---|---|---|
| `timestamp` | 記録した時刻。日本時間の ISO 8601（`+09:00` 付き・秒まで） | — |
| `device_id` | 機器の名前（下の表） | — |
| `temp_c` | 気温 | ℃ |
| `rh_pct` | 相対湿度 | % |
| `vpd_kpa` | 飽差（VPD）。同じ行の `temp_c` と `rh_pct` から計算（下の式・小数 3 桁） | kPa |
| `co2_ppm` | 二酸化炭素の濃度 | ppm |
| `soil_raw` | 土の水分の生の数（単位なし）。**大きいほど湿っている向き**。体積含水率などへの換算はしていません | — |

その機器に無い値は空欄です。

## 機器と置き方

| `device_id` | 測るもの | 置き方 |
|---|---|---|
| `node_a` | 気温・湿度・VPD | 室の空気の基準。幼木の列を囲った区画（高さ約 80 cm の囲い）の中ほど、地上 60 cm。空調（夏は冷房）の吹き出しから遠い側 |
| `node_b` | 気温・湿度・VPD | 同じ区画で、空調の吹き出しに一番近い列の先頭。高さは `node_a` とほぼ同じ。**2026-09-28 に外したため、秋の期間には行がありません** |
| `node_c` | CO2・気温・湿度・VPD | `node_b` と同じ所。CO2 を測る機器が、自分でも気温と湿度を出しています |
| `soil_a` | 土の水分（生の数） | 幼木 1 鉢の土に挿したプローブ |

- `node_b`・`node_c`・`soil_a` は同じ集め口から 1 回の読みでまとめて届くので、時刻が同じになります。`node_a` は別の集め口で、時刻が 1 秒ほどずれます。
- 読みの間隔は約 61 秒です（1 日あたり 1,414〜1,417 行）。

## 欠けた区間

隣り合う 2 行の間（と、期間の頭・尻から最初・最後の行まで）が 5 分を超える所を「穴」と数えました。

| 期間 | `node_a` | `node_b` | `node_c` | `soil_a` |
|---|---|---|---|---|
| 夏 | 0 | 0 | 0 | 0 |
| 秋 | 0 | （行なし） | 0 | 0 |

5 分以下の短い抜け（1〜2 回の読みが抜ける程度）は数に入れていません。

## VPD（飽差）の式

空気の温度で計算しています（葉の温度は使っていません）。T＝`temp_c`［℃］、RH＝`rh_pct`［%］。

```
es(T) = 0.6108 × exp( 17.27 × T / (T + 237.3) )    # 飽和水蒸気圧 [kPa]（Tetens の式）
VPD   = es(T) × (1 − RH / 100)                      # [kPa]
```

小数 3 桁に丸めています。RH が 100% の行は VPD が 0.000 になります。

## 作業の記録（加湿器・水やり・そのほかの手）

| ファイル | 期間（JST） | 行数（見出しを除く） |
|---|---|---:|
| `actions_2026-08-15_2026-09-11.csv` | 夏の区間と同じ | 54 |
| `actions_2026-10-03_2026-10-30.csv` | 秋の区間と同じ | 55 |

- 人が書いた日々の記録から、同じ期間の手を 1 行ずつ起こしました。記録が無い所を記録の値（湿度の立ち上がりなど）から推した行は、`certainty` で分けています。
- 列＝`start_jst`（始まり）・`end_jst`（終わり・一瞬の手は空欄）・`kind`・`target`・`amount`・`method`・`note`（補足）・`certainty`。
- `kind`＝`humidifier_on`（加湿器を入れていた区間）・`watering`（水やり）・`other`（そのほかの手や出来事）。
- `target`＝`hum_a`（加湿器）・`cool_a`（冷房装置）・`room`（室）・`all_pots`（全部の鉢）・`pot_a`（土の水分計を挿した鉢）・`group_a`〜`group_c`（株の組）など。
- `certainty`＝`recorded`（記録どおり）・`estimated`（記録の幅から置いた）・`inferred_from_data`（記録が無く、計器の値から推した）。
- この期間は水のやりすぎを疑っています。操作のお手本ではなく「その時に何をしたか」の記録として使ってください。

## 栽培の知識の素

`knowledge_seed.md` は、公開されている資料だけで書いた湿り気と水の管理の目安（出どころと確度の印つき）です。エージェントの専門家の役が読みます。

## 結果（`results/`）

再生と評価の出力です。表は `results/replay_table.md`、機械が読む形は `replay_<季節>_<通り>.json`（各回の計画と理由と費用）、10 分ごとの値は `replay_<季節>_<通り>_series.csv`、模擬の栽培室の合わせ具合は `sim_fit.md`、記録の自己点検は `selfcheck_<季節>.json` です。JSON の中の `sesn_…` は API の会話の番号で、鍵ではありません（鍵が無ければ読めません）。
